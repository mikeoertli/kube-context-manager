# Command help

Generated by `python3 scripts/update-help.py` from the CLI.

## `kcm`

```text
Choose Kubernetes profiles and contexts for this shell. Source kubeconfigs are shared; context selection uses environment variables and the kcmkubectl, kcmhelm, and kcmk9s shell wrappers. Expiry resets an interactive shell to local and cancels an Enter-submitted command at a stale prompt.

Usage:
  kcm [profile] [flags]
  kcm [command]

Examples:
  kcm
  kcm dev --context api-dev
  kcm prod --context api-prod --file ~/.kube/prod/config
  kcm reset

Available Commands:
  can-i              Check a live API permission without executing the action
  clear              Clear the selected context, keeping this shell's profile
  completion         Print shell completions, including profile/context names
  context            Select a context in this profile; omit name for fzf
  contexts           List available contexts, servers, namespaces, and source files
  doctor             Validate settings, profile configs, root waivers, and fzf
  exec               Run a supported client with the shell-selected context
  help               Help about any command
  import             Import a kubeconfig, suggesting the newest download and readable names
  init               Print shell integration (source it in your startup file)
  install            Import a kubeconfig, with optional readable names and copy/move
  list               List discovered contexts grouped by profile, with current selections marked
  namespace          Choose a shared namespace, or create one and switch to it
  permissions        Inspect live permissions in one namespace; never cached
  print-context-name Print this shell's selected context name
  print-kubeconfig   Print this shell's selected kubeconfig file path
  profile            Change profile; omit name to pick a profile and context
  profiles           List profile directories and default timeouts
  prompt             Print compact profile/context information for Starship
  rename             Rename kubeconfig entries in place, with an original backup
  renew              Restart or extend this shell's active context timeout
  reset              Return this shell to its default local context
  settings           Locate or initialize TOML settings
  status             Show this shell's selection and timeout in a readable summary
  unwaive            Remove a non-local root waiver
  version            Show the development version
  waive              Allow a non-local context at the kube root
  waivers            List non-local root waivers (context, source file, server)

Flags:
      --context string    Select this context in the named profile
      --file string       Disambiguate the profile's context by kubeconfig path
  -h, --help              help for kcm
      --settings string   Settings file (also KCM_SETTINGS) (default "~/.config/kcm/kcm_config.toml")

Use "kcm [command] --help" for more information about a command.
```

## `kcm profile`

```text
Without a name, select a profile with fzf, then select a context in that profile. Both selections apply together; cancellation, an empty profile, or an error leaves the shell unchanged. A named profile changes only the profile and clears its context and timeout; select a context afterwards. Switching profiles clears previous-context history. New shells start local.

Usage:
  kcm profile [name] [flags]

Examples:
  kcm profile
  kcm profile prod
  kcm context customer-a

Flags:
  -h, --help   help for profile

Global Flags:
      --settings string   Settings file (also KCM_SETTINGS) (default "~/.config/kcm/kcm_config.toml")
```

## `kcm renew`

```text
Without flags, restart the active context's configured timeout. --for sets a deadline from now; --extend adds time to an existing, unexpired deadline. Durations must be at least one second (for example 24h or 96h). These changes affect only this shell's selection, not settings, credentials, or other shells. Later context selections still apply the profile's normal timeout rules.

Usage:
  kcm renew [flags]

Examples:
  kcm renew
  kcm renew --for 24h
  kcm renew --extend 24h

Flags:
      --extend duration   Add this much time to the active deadline, e.g. 24h
      --for duration      Set expiry this far from now, e.g. 24h
  -h, --help              help for renew

Global Flags:
      --settings string   Settings file (also KCM_SETTINGS) (default "~/.config/kcm/kcm_config.toml")
```

## `kcm install`

```text
Import selected contexts into a profile. Missing choices are prompted. Remote configs require --profile with --no-prompt. Existing destinations are never overwritten. Certificate/key references are embedded; token-file and exec paths are preserved as absolute paths. --move requires importing every source context.

Usage:
  kcm install <path> [flags]

Examples:
  kcm install ./download.yaml
  kcm install ./download.yaml --profile prod --rename-context customer-a --no-prompt
  kcm install ./local.yaml --no-prompt --dry-run

Flags:
      --all-contexts            Import every context into the destination profile
      --context string          Source context to import (required when ambiguous)
      --copy                    Keep source (default)
      --dry-run                 Validate and print the plan without writing
      --filename string         Destination basename (default: source basename)
  -h, --help                    help for install
      --move                    Delete source only after a complete, verified import
      --namespace string        Installed namespace (default: preserve)
      --no-prompt               Do not prompt; preserve omitted names
      --profile string          Destination profile
      --rename-cluster string   New cluster display name
      --rename-context string   New context display name
      --rename-user string      New user display name

Global Flags:
      --settings string   Settings file (also KCM_SETTINGS) (default "~/.config/kcm/kcm_config.toml")
```

## `kcm import`

```text
With no source, use the newest filename match in ~/Desktop and ~/Downloads: a name containing .kubeconfig, or an extensionless name containing kube or config (case insensitive). --select opens a searchable picker for those matches. A supplied directory opens a searchable list of its regular files, newest first; --no-prompt uses the newest directly. A supplied file bypasses discovery. --clipboard reads kubeconfig content without clearing the clipboard; relative credential paths resolve from the current directory. Selected content is validated before import. Choose a destination profile and filename, and optionally make messy labels readable. --readable forces name updates; --skip-readable preserves labels. With --no-prompt, omitted labels are preserved unless --readable is supplied. File imports move by default, archiving the original before removing it after a verified import. --import-copy retains the source file. Moving requires every source context; use --all-contexts or --import-copy when selecting from a multi-context file. Existing destinations are never overwritten. Successful imports select the destination profile and imported context for this shell, starting its configured timeout. --import-only preserves the shell selection. With --all-contexts, select the source current-context if valid, otherwise the first context by name. Shell integration is required unless using --import-only or --dry-run.

Usage:
  kcm import [path] [flags]

Examples:
  kcm import
  kcm import --select
  kcm import --dir ~/Downloads --profile dev
  kcm import --file ./download.yaml --profile dev --name api-dev --readable --no-prompt
  kcm import ./download.yaml --profile qa --name api-qa --import-copy --skip-readable --no-prompt
  kcm import --clipboard --profile dev --name api-dev --readable
  kcm import ./download.yaml --profile dev --import-only --no-prompt

Flags:
      --all-contexts            Import every context into the destination profile
      --clipboard               Read kubeconfig content from the clipboard without clearing it
      --context string          Source context to import (required when ambiguous)
      --dir string              Browse this directory's files, newest first (no recursion)
      --dry-run                 Validate and print the plan without writing
      --file string             Explicit source file (bypasses automatic discovery)
      --filename string         Destination basename (default: source basename)
  -h, --help                    help for import
      --import-copy             Keep the source file instead of moving it (file imports move by default)
      --import-only             Import without changing this shell's profile or context
      --name string             Destination filename and suggested base for readable labels
      --namespace string        Installed namespace (default: preserve)
      --no-prompt               Do not prompt; preserve names unless --readable or rename flags are supplied
      --profile string          Destination profile
      --readable                Make selected cluster/user/context labels readable; --name supplies the base
      --rename-cluster string   New cluster display name
      --rename-context string   New context display name
      --rename-user string      New user display name
      --select                  Search Desktop/Downloads filename matches rather than choosing the newest
      --skip-readable           Preserve cluster/user/context labels without readability prompts

Global Flags:
      --settings string   Settings file (also KCM_SETTINGS) (default "~/.config/kcm/kcm_config.toml")
```

## `kcm rename`

```text
Give a kubeconfig's cluster, user, and context readable names. Defaults to this shell's selected file/context; otherwise choose a file interactively. For a supplied file, use --context to select an entry, or default to its valid current-context, then the first context by name. Other contexts are preserved, and references to renamed clusters/users are updated throughout the file. Set the file's current-context to the resulting context. Preserve namespaces unless --namespace is supplied. Refuse name collisions and archive the exact original under kube_root/archive before writing. Symlinks remain links. No cluster access, yq, or gum is required.

Usage:
  kcm rename [path] [flags]

Aliases:
  rename, make-readable

Examples:
  kcm rename
  kcm rename ./download.yaml
  kcm rename ./download.yaml --rename-cluster dev --rename-user dev-reader --rename-context dev --no-prompt
  kcm rename --rename-context api-dev --no-prompt --dry-run

Flags:
      --context string          Source context (default: shell selection, current-context, or first by name)
      --dry-run                 Validate and show the plan without creating a backup or writing
  -h, --help                    help for rename
      --namespace string        Selected context's namespace (default: preserve; empty clears it)
      --no-prompt               Apply supplied choices without prompting; preserve omitted names
      --rename-cluster string   New cluster display name; updates all references in this file
      --rename-context string   New context display name
      --rename-user string      New user display name; updates all references in this file

Global Flags:
      --settings string   Settings file (also KCM_SETTINGS) (default "~/.config/kcm/kcm_config.toml")
```

## `kcm permissions`

```text
Query the inspected context's SelfSubjectRulesReview on demand. Omit the context to use this shell's selection. Named contexts must be in the current profile; use --file for duplicate names. Does not switch contexts or modify kubeconfigs. The compact table preserves resource-name restrictions; --details prints the full returned status as JSON. Incomplete results are labeled: missing rules then mean unknown, not denied. No cache, automatic checks, or picker queries.

Usage:
  kcm permissions [context] [flags]

Examples:
  kcm permissions
  kcm permissions customer-a -n app
  kcm permissions --details

Flags:
      --details                    Print the full returned rule status as JSON after the scope header
      --file string                Disambiguate by source kubeconfig path within this profile
  -h, --help                       help for permissions
  -n, --namespace string           Namespace (default: inspected context's namespace, or default)
      --request-timeout duration   Timeout for the live check; must be positive (default 10s)

Global Flags:
      --settings string   Settings file (also KCM_SETTINGS) (default "~/.config/kcm/kcm_config.toml")
```

## `kcm can-i`

```text
Use SelfSubjectAccessReview to check one action with the inspected context's credentials. Resource names, singular names, and short names are resolved through live API discovery. Use --subresource for log, exec, or another subresource. Cluster-scoped resources are detected automatically; -A checks a namespaced action across all namespaces. Does not execute the action, switch context, or cache results. Prints yes or no: exit 0 means allowed, 1 means not allowed, 2 means the check failed or is inconclusive. An allowed result does not guarantee that admission policies or other execution requirements will permit the actual operation.

Usage:
  kcm can-i <verb> <resource[.group][/name]> [flags]

Examples:
  kcm can-i list pods -n app
  kcm can-i delete deployments.apps --context customer-a -n app
  kcm can-i get pods/my-pod --subresource log -n app
  kcm can-i list nodes
  kcm can-i list pods -A

Flags:
  -A, --all-namespaces             Check the action across all namespaces
      --context string             Inspect a context in this profile without switching
      --file string                Disambiguate by source kubeconfig path within this profile
  -h, --help                       help for can-i
  -n, --namespace string           Namespace (default: inspected context's namespace, or default)
      --request-timeout duration   Timeout for the live check; must be positive (default 10s)
      --subresource string         Check a subresource, such as log or exec

Global Flags:
      --settings string   Settings file (also KCM_SETTINGS) (default "~/.config/kcm/kcm_config.toml")
```
